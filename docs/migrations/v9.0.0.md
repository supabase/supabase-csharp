# Migrating to 9.0.0

This guide covers the breaking changes planned for 9.0.0 and what you need to do about them.
Each entry is deprecated in 8.x first, so you can migrate before upgrading.
For the full list of every change, see [`CHANGELOG.md`](../../CHANGELOG.md).

All packages are versioned in lockstep, so this major bump applies to every
`Supabase.*` package at once.

## 1. `IGotrueClient.SignUp` is removed in favor of `SignUpAsync`

Both `SignUp(string email, string password, SignUpOptions? options)` and
`SignUp(SignUpType type, string identifier, string password, SignUpOptions? options)` are
`[Obsolete]` since 8.x and are removed in 9.0.0.

**Why:** `SignUp` returns a `Session?` that means two different things: a signed-in session when
the project does not require confirmation, and a token-less carrier of the pending user when it
does. It also ignores `SignUpOptions.FlowType` and `SignUpOptions.Channel`, so a PKCE email
sign-up sent no code challenge and a phone sign-up could not choose WhatsApp. `SignUpAsync`
returns a `SignUpState` that keeps those cases apart, honors both options, and takes a
`CancellationToken`.

**What you need to do:**

```csharp
// Before
var session = await client.SignUp(email, password);
var signedIn = session?.AccessToken != null;

// After
var signedUp = await client.SignUpAsync(SignUpType.Email, email, password);
var signedIn = signedUp.Session != null;
var user = signedUp.User;
var verifier = signedUp.PKCEVerifier;
```

- `signedUp.Session` is the session the user is signed in with, or `null` while they still have to
  confirm. The client adopts it, persists it and raises `SignedIn`, as `SignUp` did.
- `signedUp.User` is the signed-up user, including one awaiting confirmation.
- `signedUp.PKCEVerifier` is set for an email sign-up with `FlowType = OAuthFlowType.PKCE`. Pass it
  with the code from the confirmation link to `ExchangeCodeForSession`.
